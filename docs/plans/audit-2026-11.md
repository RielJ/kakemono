# Code audit, November 2026

This audit covers the whole workspace after the variety-sources work (Tasks 1–26). Five read-only reviewers
checked it against the Rust best-practices handbook (Apollo) and the Tauri v2 skill. Their full reports are in
`/tmp/kk-audit/{engine,platform,core,sources,tauri}.md`. A strict clippy run (pedantic plus `unwrap_used`,
`expect_used`, `panic`, `indexing_slicing`) gave 2,938 warnings. Its raw output is in
`/tmp/kk-audit/clippy-strict-uniq.txt`.

Overall the code is in good shape:

- No production code can panic. Every `unwrap`, `expect` and indexing hit outside tests is guarded or on a
  constant.
- All 32 `unsafe` blocks have `SAFETY` comments, and AppKit calls are checked to run on the main thread.
- Tauri commands are async and register through one handler.
- The `thumb://` protocol is a real allowlist and checks symlinks again before serving.

The problems are at the edges: concurrent file writes, operations with no timeout, and permissions wider than the
app needs.

"Checked" below means the lead reviewer read the cited code and confirmed the finding. Other findings were
confirmed by reading only, and none were reproduced at runtime.

## High: data loss, hangs, orphaned processes

| # | Where | Problem | Fix | Checked |
|---|---|---|---|---|
| H1 | `crates/config/src/edit.rs:249-266` | Every config write in one process uses the same temp file, `.config.toml.tmp.<pid>`, opened with `truncate`. The UI's `save_config` and the picker's `save_custom` and `save_edge` run on separate blocking threads. They can interleave and rename a half-written file into place. Even with unique temp names, two concurrent read-modify-write patches lose one edit. | Use a unique temp file (`create_new` with a counter, like `engine/src/state.rs:472`) and a per-path lock held across the whole read-modify-write. Add a two-thread patch test. | yes |
| H2 | `crates/ui/src-tauri/src/commands.rs:293-304` | The picker's Favorite copies with `fs::copy` to `favorites/<file_name>`, so two folders that both hold `1.jpg` overwrite each other's favorite. The daemon's own favorite (`engine/src/files.rs:477`) never overwrites. | Delete the UI copy. Send the path to the daemon's `Favorite`, or reuse `copy_unique`. Add a name-collision test. | yes |
| H3 | `platform/src/linux/backends/{kde,xfce}.rs`, `windows/setter.rs:75` | KDE `evaluateScript`, XFCE D-Bus calls and the Windows reply wait have no timeout (zbus 5 sets no default). The engine holds its op lock during `set`, so a frozen plasmashell, xfconfd or Explorer blocks every next, prev and reload. | Wrap every `set` in `tokio::time::timeout`, in `ResilientSetter` or the engine. | reported |
| H4 | `platform/src/linux/backends/persistent.rs:198-214` | When the new persistent setter (swaybg and similar) is alive but its process name doesn't match (`env …`, `sh -c exec …`), `replace` returns an error without stopping it. If `write_record` fails, the old setter is already stopped and the new one is untracked. Each later `set` adds another orphan. | Stop the new pid on both error paths. Write the record before stopping the old setter. | yes |
| H5 | `crates/sources/src/http.rs:18,57`, `download.rs:258-270` | The 30 s `timeout()` is the total request deadline, so it also covers the image body. A large image on a slow link always fails, and transport errors are not retried. Downloads have no size cap, while `engine/src/manual.rs` caps at 64 MiB. | Use `connect_timeout` and `read_timeout`, with no total deadline for image bodies. Add one shared `MAX_IMAGE_BYTES` that both download paths enforce while streaming. | yes |
| H6 | `crates/ui/src-tauri/src/daemon_link.rs:78-101` | One shared daemon connection is locked for up to 30 s per request. A dropped URL (`Fetch`) blocks tray Next, Prev and Pause, status and save-reload. When the UI times out it reports "daemon unreachable", but the daemon still sets the wallpaper. | Send `Fetch`, `DownloadNow` and `CheckSource` on their own connection, as `events.rs:156` does. Add a separate `timeout` error kind. | reported |
| H7 | `crates/engine/src/downloader.rs:446-464` | `record_seen` reads, appends and renames through one fixed `ledger.tmp`, with no lock. The first background fill can overlap a `change_on_start` download, or `download_now` can overlap a tick. The same image is then saved twice, a ledger entry is lost, or the rename fails. | Use one per-source async mutex around download and record, plus a unique temp file. | yes |

## High: security (Tauri)

| # | Where | Problem | Fix |
|---|---|---|---|
| S1 | `capabilities/default.json` | `autostart:default` is unused by the frontend, but it lets page JS toggle autostart and skip `set_start_at_login`, which keeps the UI and daemon entries in step. `core:window:allow-close` and `opener:allow-reveal-item-in-dir` are unused. `opener:allow-open-path` on `$HOME/**` can launch any file in home, and still fails for `/Volumes`. ## Refactors (themes across crates)

1. **One atomic-write helper.** Four copies exist: `config/edit.rs`, `engine/state.rs`, `engine/facts.rs:467` and
   `downloader.rs:459`. Two of them use fixed temp names. Make one helper that uses a unique `create_new` temp
   file, fsyncs the file and its folder, renames, and handles symlinks. This fixes H1, H7 and M4 at their root.
2. **One favorites path.** Use the daemon's `copy_unique`. This fixes H2.
3. **Errors.**
   - Use typed errors in the engine, not `Fetch(Vec<String>)`, `Files(String)`, `Manual(String)`, or the
     `String` results of `check_source` and `download_now`.
   - Write one `{kind, message}` serializer in the Tauri crate. Today there are three, and they lose kinds when
     converting.
   - Fix the double-printing in M11.
4. **Shared protocol types.** The doctor payload is defined twice (`cli/src/daemon/server.rs:59` and
   `ui/src-tauri/src/commands_desktop.rs:27`), and `theme` is a plain `String`. Move both into `protocol` and
   export the Tauri IPC reply types to TS with ts-rs, instead of hand-written types.
5. **Split large files.**
   - `engine.rs` (975 lines): split into ops, errors, deps and Go-compat text.
   - `platform/linux/mod.rs` (1,373 lines): split into resilient and live.
   - `commands_sources.rs` (1,292 lines): split into `sources/{mod,folders,listing,drop}.rs`.
   - `commands.rs` (780 lines): split into error, config, control and platform.
6. **Remove duplication.**
   - Interval parsing: `rotation.rs:289` and `downloader.rs:308`.
   - The Go error mappers: `go_stat_error` and `go_reason`.
   - `host()`: macOS and Windows have copies.
   - The theme/signal hub: three versions, two of them word-for-word copies.
   - CLI runtime builders (3), `absolute` (2) and `detach` (2).
   - Socket and runtime directory: computed in two crates.
   - Provider helpers: `null_default`, base-URL trimming, and the per-provider status check. Merge the last into
     the shared `check_status` from M1.
7. **Lints and CI.**
   - Add `unwrap_used`, `expect_used`, `unsafe_code` (with an `#[expect]` at each FFI module) and `dbg_macro` to
     `[workspace.lints]`.
   - Add a `clippy.toml` with `allow-unwrap-in-tests` and `allow-expect-in-tests`.
   - Run clippy on Linux and Windows in CI. The macOS run never sees `linux/*` or `windows/*`.
8. **Dependencies.**
   - Remove the unused `chrono` (protocol and sources), `futures` and `insta` (engine, sources) and the unused
     `live` feature.
   - Move `async-trait` in the engine to dev-dependencies.
   - Remove the npm `@tauri-apps/plugin-autostart`.
   - Remove the stale "Task 40" comments in `Cargo.toml`.
9. **Tests.**
   - Replace real sleeps with paused time: `pick_from_disk.rs:610`, `engine_core.rs:622`, `reload_setter.rs:241`
     and the `hooks.rs` `settle` helper. Several of these assert that something did not happen, which passes on
     a slow machine for the wrong reason.
   - Add concurrency tests for every shared file writer.
   - Share the fixture helpers that are copied across three engine test files.
10. **Docs.** 236 public functions that return `Result` have no `# Errors` section. Fix these with the lint, not
    by hand. Stale module docs are in `engine/events.rs`, `engine/lib.rs` and `pool::pick`.

## Suggested order

1. **Data safety:** refactor 1 (atomic write and lock) to fix H1, H7 and M4; then H2 with refactor 2, then M7.
2. **Hangs:** H3, H6, H5, H4 and M9.
3. **Tauri security:** S1 and S2.
4. **Other correctness:** M1–M3, M5, M6, M8, M10–M12.
5. **Cleanup:** refactors 3–10. Lints come last, because enabling them on the current code gives hundreds of
   warnings at once.

## Not a problem (leave as is)

- `Deps` trait objects in the engine: one dynamic call per operation, which is a reasonable seam for tests.
- `fetch_url` downloads before taking the op lock, on purpose.
- Trash then `next` fails: the file is already moved and only the error is shown. This matches the Go app and is
  a product decision.
- The duplicate crate versions in `Cargo.lock` come from tauri, gtk and scraper.

## Could not confirm

- Whether a session bus ever answers a frozen peer with `NoReply` (this decides whether H3 lasts minutes or
  forever).
- Whether cancelling the Windows named-pipe `accept` inside `select!` is safe, and whether another process can
  take over the pipe name first.
- Whether Tauri adds a nonce to `style-src`, which would make `'unsafe-inline'` ineffective.
- Whether the Wallhaven API ever sends `null` in the M10 fields.
- Whether `hard_link` in `download.rs:288` fails on exFAT, FAT or SMB download folders.
- Unsplash's terms ask apps to call `download_location` when a photo is used. Nothing does this today.
